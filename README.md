## Як відкрити

Відкрийте `index.html` у браузері (Chrome, Firefox, Edge, Safari). Інтернет не потрібен: шрифти й зображення лежать у репозиторії.

## Як ми працюємо

Над сайтом працюють двоє розробників: один робить версію на WordPress, другий — на Django. Дизайн у них спільний.

| Гілка | Хто працює | Що там |
|---|---|---|
| `main` | спільна | Макет: HTML, CSS, JS, зображення, генератор сторінок. Джерело дизайну для обох версій |
| `wordpress` | Serhii | Тема WordPress — у папці `wp-theme/` |
| `django` | розробник Django | Проєкт Django — у папці `django/` |

Правила:

1. Кожен пушить лише у свою гілку. У чужу гілку й напряму в `main` не пушимо.
2. Зміни дизайну (верстка, стилі, скрипти, зображення, генератор) — тільки в `main` і тільки через Pull Request, який схвалює власник репозиторію:
   ```
   git switch -c design/korotka-nazva origin/main
   # правки, коміт
   git push -u origin design/korotka-nazva
   ```
   далі на GitHub — Pull Request у `main`.
3. Оновлення дизайну у свою гілку:
   ```
   git switch django        # або wordpress
   git fetch origin
   git merge origin/main
   ```
4. Гілки `wordpress` і `django` між собою не зливаються.
5. Перед Pull Request у `main` — перевірки: W3C, html-validate, stylelint, ESLint, axe (WCAG 2.2 AA), ширини 320–1920 px з A / A+ / A++.
6. Коміти — під своїм ім’ям і поштою, прив’язаною до GitHub (`git config user.name`, `git config user.email`). Повідомлення комітів — українською.
7. У репозиторій не потрапляють паролі, ключі, файли `.env`, бази даних і персональні дані.

Правила змісту для обох версій:

- Назва в текстах — «НРЦ «Оберіг»». Повна офіційна назва — лише в шапці, підвалі й мета-тегах.
- Жодних діагнозів і приватних даних дітей та працівників; фото дітей — лише зі згодою батьків. Жодної реклами.
- Доступність WCAG 2.2 AA; A+ / A++ збільшують лише текст; за замовчуванням — світла тема.

## Структура

```
index.html      головна сторінка
404.html        сторінка «Сторінку не знайдено»
pro-nas/ … bezpeka-ta-zakhyst/   8 розділів меню: index.html (огляд розділу) + підсторінки
novyny/         список новин і шаблон новини
kontakty/       контакти
tools/          генератор сторінок (Python 3, без додаткових бібліотек)
css/style.css   стилі
css/fonts.css   підключення шрифтів
js/main.js      меню, панель доступності, тема, слайдер, анімації
js/prefs.js     тема й налаштування доступності до показу сторінки (запам’ятовуються між сторінками і вкладками) і прелоадер
img/            логотип, ілюстрація, іконки, картинка для соцмереж
fonts/          шрифти Nunito і Unbounded (SIL Open Font License)
```

## Що є в макеті

- Панель доступності: збільшення тексту (A / A+ / A++), контрастний режим, підкреслення посилань; світла і темна тема.
- Меню з підменю; на вужчих екранах — кнопка-бургер праворуч і панель меню збоку.
- Прелоадер: при першому відкритті сайту у вкладці — коротка заставка з логотипом (~1,5 с); на інших сторінках з’являється лише, якщо вантаження триває довше 0,4 с. З «менше руху» в системі — без заставки й обертання.
- Головна: перший екран, швидкі посилання, «Про НРЦ «Оберіг»» (з дошкільним відділенням), новини (слайдер), документи (ст. 30 ЗУ «Про освіту»), безпека та захист, запрошення, «Наші спонсори», контакти з формою запитання.

- Внутрішні сторінки за ТЗ: хлібні крихти, бічне меню розділу, блоки документів (PDF), таблиці, картки працівників, кроки, сторінка 404.

## Як оновити сторінки

Структура меню і зміст-приклади записані в `tools/site_map.py`. Після зміни виконайте з кореня репозиторію:

```
python tools/build_pages.py
```

Скрипт бере шапку і підвал з `index.html` (позначки `<!-- build:menu -->` і `<!-- build:footer -->`), оновлює в них меню і заново створює всі внутрішні сторінки. Сторінки, створені скриптом, вручну не правити — зміни зітруться.

## Стан

Це макет: документи, новини, ПІБ заступників і логотипи спонсорів — приклади («додасть адміністрація»), форма нічого не надсилає. Далі сторінки буде перенесено в тему WordPress (гілка `wordpress`) і в проєкт Django (гілка `django`).

Перевірено (усі 59 сторінок): валідатор W3C і html-validate (0 помилок), stylelint і ESLint (recommended), axe-core WCAG 2.2 AA (0 порушень у світлій, темній і контрастній темі та в мобільному меню), ширини 320–1920 px × A / A+ / A++, 0 битих посилань.

`404.html` на хостингу треба вказати як сторінку помилки (наприклад, `ErrorDocument 404 /404.html` в `.htaccess`). У WordPress її замінить шаблон `404.php`.

Коли буде домен, у `<head>` треба додати `canonical` і повні адреси для `og:image`/`og:url` (там є коментар-нагадування).
